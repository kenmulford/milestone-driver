## After a `/code-review` fix, before committing

The branch that reaches this file belongs to the caller, which runs `/code-review` and counts its in-scope findings before reading it (`skills/solve-issue/SKILL.md (No in-scope findings → commit directly)`). Reaching this file therefore means at least one in-scope finding was fixed this cycle. A review that returned no in-scope finding commits directly and never reads this file - nor does the cycle cap below ever bind on it, since a cycle is a review **plus** the fix it triggers.

### After a fix

Evaluate the branches **in order**.

- **Document-only** (every path the delta touches is `*.md` / a README / doc text, and **nothing** is under `sourceGlobs`): commit directly, no re-run - `tests-green` no-ops on doc-only, and `/code-review` need not be re-run for a doc-only fix.
- Otherwise run `${CLAUDE_PLUGIN_ROOT}/scripts/classify-delta.<sh|ps1> <repo-root>` (pwsh on Windows, bash elsewhere) and **take the branch it prints** - `comment-only` or `code-changed` on stdout, one reason token on stderr for `code-changed`, always exit 0. **The verdict is the script's, never the agent's**: never re-derived, never overridden. What counts as a comment, and every input shape the rule was built against, live in `scripts/classify-delta.sh (comment-only delta classifier)` and `tests/classify-delta.cases.tsv`.
  - **`code-changed`:** re-run `unitTestCmd` if defined (skip if absent), then re-run `/code-review` - the fresh review must be the **last action before commit**, and the procedure does not loop past a second clean review. `POST_REVIEW_CHANGES: yes` is the machine-checkable signal that the re-review is due **on a `code-changed` delta**; a `sourceGlobs` change triggers it independently as a backstop, so a re-dispatch that changed source is always re-reviewed even if the field is `no`. On a `comment-only` delta neither the field nor the backstop fires.
  - **`comment-only`:** **stage in one Bash call, then `git commit` in the next** - never `git add … && git commit …` in a single call, where `tests-green` inspects the index before the `git add` has run and sees nothing staged. No `unitTestCmd` re-run, no `/code-review` re-run. The finding's resolution is still recorded in the **Code Review** section (step 6.3).

`hooks/tests-green.sh (Runs unitTestCmd when staged files touch sourceGlobs)` is a `PreToolUse` hook reading `git diff --cached --name-only` **before** the Bash call runs, so it sees only what an **earlier** call staged. It fires under every branch above and decides on **path**: a comment-only edit inside a `sourceGlobs` file runs the suite there and blocks on red at exit 2. **It is not a guaranteed second suite run** - it exits 0 having run nothing when `unitTestCmd` is absent from the profile (supported; `docs/profile-schema.md (What command runs the unit tests? Absent →)`), when the staged tree matches the last green run's stamp, when `jq` is absent, or when `CLAUDE_HOOK_DISABLE_TESTS_GREEN=1` is set. On the `comment-only` branch, which skips the orchestrator's own re-run, each means no suite runs at all.

**Cap: review→fix cycles, keyed to step 6.1's classifier verdict.** A cycle is one `/code-review` run plus the fix it triggers, and on a `code-changed` delta **the fresh review is the last action before commit**; no verdict skips that review. `deep`: at most 2 cycles, any in-scope finding surviving the 2nd fix parks. `standard`: 1 cycle, a 2nd only when the most recent review returned a **Critical or Important** finding; a Minor is disposed `accepted (rationale: <…>)` in the Code Review section (step 6.3), and accepting changes no code, so no re-review and no 2nd cycle fire. `shallow`: 1 cycle, a 2nd impossible.

**Before a 2nd cycle starts, `scripts/classify-review-depth.{sh,ps1}` re-runs against the post-fix diff**, and decides whether that cycle happens at all: a verdict dropping to `shallow` ends the loop, one rising to `deep` runs the 2nd cycle already granted but grants no 3rd. The cap stays whatever the **first** verdict set. **A second cycle returning any Critical or Important finding parks the issue `needs design`, with the park comment stating that a second review round returned a Critical or Important finding. No third cycle runs.**

**Non-convergence parks only a finding its profile fixes**; the caller's park-trigger bullet fires at any severity. Park with `needs design` or `blocked`, the current diff state as evidence.
